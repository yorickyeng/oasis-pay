# Команды банка oasis pay

Все команды выполняются из корня проекта при запущенном Docker Desktop:

```sh
./oasis help
```

## Четыре основные команды

| Задача | Команда | Результат |
|---|---|---|
| Подготовить новый TLS | `./oasis tls-issue` | Определяет IPv4 Wi-Fi и выпускает кандидат, активный сертификат сохраняется |
| Применить подготовленный TLS | `./oasis tls-apply` | Снимок базы и ключей, переключение сертификата и настроек, запуск и healthcheck |
| Полностью запустить банк в текущей сети | `./oasis network` | Определение IPv4, первый запуск либо необходимая смена TLS, вывод параметров |
| Освободить обе роли | `./oasis clients-reset` | Снимок базы и ключей, удаление регистраций без связанных платежей |

Вручную указать IP: `./oasis tls-issue 192.168.1.10` или `./oasis network 192.168.1.10`. Это также подходит для Ethernet. Автоопределение ищет именно Wi-Fi, а не маршрут VPN. Некорректный IPv4 отклоняется до запуска обслуживания.

`tls-issue` можно выполнять без остановки банка. Кандидат сохраняется в `tls-pending.json`; повторный выпуск заменяет прежний кандидат. `tls-apply` применяет именно его, не определяя IP повторно. При изменившихся исходных настройках нужен новый выпуск.

`network` сохраняет сертификат, если IP прежний, сертификат и отпечаток корректны, а до окончания срока больше суток. Иначе выпускает и применяет новый. Срок сертификата — 30 дней. Команда не сбрасывает клиентов и платежи.

После смены TLS откройте параметры банка на покупателе, введите новый URL и TLS SHA-256 из консоли, подтвердите прежним кодом покупателя. Для кассы обновите эти данные при следующем обращении к банку, например продлении регистрации. Коды ролей, ключ банковской подписи и история сохраняются; приложения очищать не нужно. Доверие не обновляется на телефонах автоматически.

Если `tls-apply` не смог запустить банк, CLI пытается вернуть прежние TLS-настройки. При истёкшем/повреждённом прежнем сертификате автоматическое восстановление может не пройти: смотрите `status`, `logs` и резервную копию. При отключении питания запустите `status`, затем `network`, прежде чем продолжать работу.

## Регистрации устройств

```sh
./oasis clients
./oasis clients-reset terminal
./oasis clients-reset buyer
./oasis clients-reset            # обе роли
```

`clients` показывает ID, роль, модель из сертификата, срок регистрации и признак отзыва. `sdk_gphone64_arm64` — модель эмулятора. Роли: одна касса (`terminal`) и несколько покупателей (`buyer`), у каждого свой счёт и постоянный номер.

**Сброс выполняется сразу, без дополнительного вопроса.** `clients-reset buyer` выбирает всех покупателей и откажет целиком, если хоть один связан с платежом. Он освобождает выбранные роли для регистрации других устройств. Ключи банка, коды подключения и балансы сохраняются; эмуляторы после сброса не следует регистрировать раньше телефонов.

Сброс откажет, если хотя бы одно выбранное устройство связано с платежом любого статуса. Вся операция откатывается; записи платежей, проводок и событий не удаляются. Это не команда полного обнуления финансового стенда. Для отдельного эксперимента после платежей используйте отдельный проект Docker с собственными томами и портами.

Перед сбросом закончите работу приложений, проверьте их локальные счета: банк не видит ещё не доставленные офлайн-счета. Команда не очищает журнал на телефоне. Не удаляйте приложение и не очищайте его данные при незавершённой операции.

## Запуск, состояние и остановка

```sh
./oasis network       # первый запуск или новая сеть
./oasis start         # повторный запуск без смены TLS
./oasis status       # состояния контейнеров и порты
./oasis logs         # последние 100 строк банка
./oasis show         # URL, TLS SHA-256, коды ролей
./oasis ledger       # балансы и результаты платежей
./oasis stop         # остановка с сохранением базы и ключей
./oasis test         # тесты в отдельной временной схеме
```

`./oasis start <IPv4>` по-прежнему поддерживается: создаёт новый банк или проверяет совпадение адреса существующего. Для смены адреса используйте `network`.

Внутренняя проверка HTTPS с проверкой сертификата и TLS 1.3:

```sh
docker compose exec -T bank python bank.py --state /var/lib/oasis/keys health && echo 'Банк и база доступны'
```

Она не проверяет путь от телефона. Успешный `nc` на Mac тоже не означает доступность с телефона.

## Резервные копии

```sh
./oasis backup
```

Кратко останавливает банк и сохраняет согласованный снимок в `backups/<время>-<случайный-суффикс>/`, затем запускает банк обратно. `tls-apply`, смена TLS через `network` и `clients-reset` делают такой снимок автоматически до изменения данных.

Содержимое: `database.dump` (PostgreSQL custom format), `bank-keys.tar` (каталог `keys`, включая ключи и настройки), `env`, `context.txt` (проект и порты), маркер `COMPLETE`. Без `COMPLETE` снимок не считается завершённым. Папки приватные и исключены из Git; не публикуйте их. Резервные копии не удаляются автоматически.

Восстановление требует остановленного банка и согласованного возврата базы вместе с ключами. Не откатывайте только базу после новых платежей: локальные журналы устройств также требуют сверки. `docker compose down -v` удаляет тома и не подходит для обычной остановки.

Обслуживание одного проекта сериализуется каталогом `.oasis-lock-<проект>/`. При аварийном завершении он может остаться. Прежде чем вручную удалить его файл `pid` и пустой каталог, проверьте, что процесс с этим PID и другие команды обслуживания действительно завершены.

## SQL-просмотр

Команды ниже — для стандартного проекта с `.env`:

```sh
docker compose exec -T postgres psql -U oasis -d oasis -P pager=off -c \
  'SELECT id, role, to_timestamp(valid_to) AS valid_until, revoked, last_sequence FROM devices ORDER BY role;'

docker compose exec -T postgres psql -U oasis -d oasis -P pager=off -c \
  'SELECT id, balance, balance / 100.0 AS rub FROM accounts ORDER BY id;'

docker compose exec -T postgres psql -U oasis -d oasis -P pager=off -c \
  'SELECT transaction_id, operation_id, amount, status, received_at, fulfilled_at FROM payments ORDER BY operation_id;'

docker compose exec -T postgres psql -U oasis -d oasis -P pager=off -c \
  'SELECT operation_id, debit_account, credit_account, amount FROM ledger ORDER BY operation_id;'

docker compose exec -T postgres psql -U oasis -d oasis -P pager=off -c \
  'SELECT id, operation_id, event, created_at FROM outbox ORDER BY id;'

docker compose exec postgres psql -U oasis -d oasis
```

В psql: `\dt` — таблицы, `\d devices` — схема, `\q` — выход. Суммы в копейках. `PAID` — оплата, `DECLINED` — отказ, `CANCELLED` — подписанная отмена без списания. `received_at` — получение результата кассой, `fulfilled_at` — подтверждённая выдача. Не меняйте эти поля вручную.

## Другой проект Docker

Если ранее создан отдельный hotspot-стенд, выбирайте его явно в текущем окне Терминала:

```sh
export COMPOSE_PROJECT_NAME=oasis-pay-hotspot
export OASIS_ENV_FILE=.env.hotspot
./oasis network
./oasis clients
./oasis show
```

Все команды `./oasis` учитывают обе переменные. Прямые команды `docker compose` требуют `--env-file "$OASIS_ENV_FILE"`; имя проекта берётся из экспортированной переменной. При работе нескольких проектов одновременно задавайте также разные `OASIS_BANK_PORT` и `OASIS_DB_PORT`. Для стандартного проекта в новом окне используйте:

```sh
unset COMPOSE_PROJECT_NAME OASIS_ENV_FILE OASIS_BANK_PORT OASIS_DB_PORT
```

## USB вместо Wi-Fi

```sh
ADB="$HOME/Library/Android/sdk/platform-tools/adb"
"$ADB" devices -l
"$ADB" -s RFCY7126QWP reverse tcp:8443 tcp:8443
"$ADB" -s RFCY7126QWP reverse --list
"$ADB" -s RFCY7126QWP shell 'toybox nc -z -w 3 127.0.0.1 8443; echo TCP_EXIT:$?'
```

`TCP_EXIT:0` означает успешный TCP. В приложении — `https://127.0.0.1:8443`, актуальный TLS-отпечаток и код выбранной роли из `./oasis show`. Банк и USB должны оставаться подключёнными. При другом порте банка замените оба номера в `reverse`, адресе и проверке. Для другого устройства замените серийный номер значением из `devices -l`.

```sh
"$ADB" -s RFCY7126QWP reverse --remove tcp:8443
```

## Ответы приложения

- `Нет связи с банком` — сетевая ошибка; проверяйте подключение именно с телефона.
- `Защищённое подключение ... не установлено` — адрес, отпечаток, время или срок сертификата. После смены сети сначала выполните `network`, затем обновите данные на телефоне.
- `Банк не подтвердил доступ` (в 1.1: «Подтвердите регистрацию покупателя в банке») — `unauthorized`. При регистрации проверьте код выбранной роли; при работе покупателя — регистрацию и токен.
- `Продлите или восстановите регистрацию устройства в банке` — занятая роль (`enrollment_unavailable`) либо истёкший сертификат кассы. Начните с `./oasis clients`.

Код роли вводится при регистрации. Токен покупателя банк выдаёт автоматически; вручную вместо кода его вводить не нужно.
